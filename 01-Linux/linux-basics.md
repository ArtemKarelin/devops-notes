#Базовые команды Linux

##Что вокруг

Терминал всегда стоит в какой-то директории, и первые команды отвечают на три вопроса: где я, что здесь лежит и как попасть в другое место.

pwd                # показать, где я сейчас
ls                 # что лежит в текущей директории
ls -l              # то же, но подробно: права, владелец, размер, дата
ls -la             # плюс скрытые файлы (их имена начинаются с точки)
cd /var/log        # перейти в /var/log
cd ..              # подняться на уровень выше
cd                 # вернуться в домашнюю директорию (то же самое, что cd ~)


Пути бывают абсолютные и относительные. Абсолютный начинается с корня / и работает откуда угодно: 

/var/log/nginx

Относительный отсчитывается от текущего места: если вы стоите в /var/log, то cd nginx приведет туда же

Две точки .. означают родительскую директорию,
а тильда ~ – домашнюю.

В выводе ls -l пока достаточно смотреть на две вещи: имя и первый символ строки. Если строка начинается с d, перед вами директория, если с дефиса, то обычный файл.

##Чтение файлов командой cat

cat печатает содержимое файла прямо в терминал:

cat /etc/os-release

	NAME="Ubuntu"
	VERSION_ID="24.04"
	PRETTY_NAME="Ubuntu 24.04 LTS"
	...
Для конфигов и коротких файлов это самый быстрый способ заглянуть внутрь. Файл на десять тысяч строк cat тоже напечатает, но читать его так неудобно, поэтому для длинных файлов есть less, он будет ниже, в списке утилит на потом.

##Поиск по содержимому через grep

grep ищет в файлах строки по тексту. Из всей десятки эта команда чаще всего выручает в реальной работе: что-то сломалось, и вы ищете в логах, что именно случилось.

grep error /var/log/app.log        # строки со словом error
grep -i error /var/log/app.log     # без учета регистра: error, Error, ERROR
grep -n error /var/log/app.log     # показать номера найденных строк
grep -r "listen" /etc/nginx/       # искать во всех файлах директории

Еще grep постоянно используют в связке с другими командами через символ |:

Пайп: вывод одной команды на вход другой

cat access.log | grep "500"
cat достает все строки лога grep оставляет только нужные

акая связка называется пайпом, и на ней строится повседневная работа в терминале: одна команда достает данные, вторая фильтрует, третья считает.

##Создание файлов и папок

mkdir создает директорию, touch – пустой файл:

mkdir reports                  # директория reports
mkdir -p apps/web/logs         # сразу вся вложенность
touch notes.txt                # пустой файл
echo "hello" > notes.txt       # записать строку в файл
cat notes.txt                  # проверить: hello

Флаг -p избавляет от создания вложенных директорий по одной. А символ > в примере с echo перенаправляет вывод команды в файл вместо экрана; если файл уже существует, его содержимое будет перезаписано.

##Копирование и перемещение

cp config.yaml config.yaml.bak    # копия рядом: классический бэкап перед правкой
cp -r site/ site_backup/          # директорию целиком, с содержимым
mv config.yaml /etc/myapp/        # переместить в другое место
mv old_name.txt new_name.txt      # переименовать
Отдельной команды «переименовать» в Linux нет: переименование – это перемещение в ту же директорию под новым именем, поэтому оба случая закрывает mv. И обратите внимание на флаг -r у cp: он означает «рекурсивно», то есть со всем содержимым, и без него директория не скопируется.

##Удаление файлов командой rm

rm notes.txt           # удалить файл
rm -r old_project/     # удалить директорию со всем содержимым

Здесь стоит притормозить. Корзины в терминале нет: что удалено через rm, то удалено насовсем, и команда не переспрашивает. Поэтому перед rm -r полезна привычка проверить, где вы находитесь (pwd) и что именно собираетесь удалить (ls). Вдвойне это касается удаления с sudo.

##Права на файлы
У каждого файла в Linux есть права: кто может его читать, изменять и выполнять. chmod эти права меняет:
chmod +x deploy.sh       # разрешить запускать файл как программу
chmod 644 config.yaml    # числовая запись прав

Самый частый сценарий для новичка – первый: вы написали скрипт, а система отказывается его запускать, потому что у файла нет права на выполнение. chmod +x это право добавляет. Числовая запись вроде 644 или 755 кодирует права для владельца файла, его группы и всех остальных; расшифровывать ее пока не обязательно, эта тема целиком разбирается дальше, в шаге про права доступа.

##Права администратора и sudo

sudo выполняет команду от имени администратора, которого в Linux называют root:

sudo apt install htop          # установить пакет
sudo systemctl restart nginx   # перезапустить службу
sudo cat /etc/shadow           # прочитать файл, закрытый для обычных пользователей

Вы уже видели sudo в прошлом шаге при установке nginx. Правило простое: все, что меняет систему (установка пакетов, управление службами, правка системных конфигов), требует sudo, а осмотр и работа со своими файлами нет. Добавлять sudo к каждой команде «на всякий случай» – плохая привычка: чем меньше команд выполняется с правами root, тем меньше шансов случайно сломать систему.

##Что учить после этой десятки
Десятка выше закрывает навигацию и работу с файлами. Следующий слой – утилиты, которые превращают терминал в полноценный рабочий инструмент. Учить их все сразу не нужно, достаточно знать, что они существуют, и брать по мере надобности.

Утилита		Зачем нужна
nano		простой текстовый редактор прямо в терминале
vim		редактор, который есть на любом сервере
less		листать длинные файлы и логи
tail -f		смотреть лог в реальном времени, пока сервис в него пишет
head		показать первые строки файла
find		искать файлы по имени, размеру или дате
ps, top		список процессов и нагрузка на систему
kill		остановить процесс
systemctl	управлять службами: запуск, остановка, автозагрузка
df -h, free -h	сколько занято диска и оперативной памяти
curl		отправить запрос на сайт или API прямо из терминала
ssh, scp	подключиться к удаленному серверу и передать на него файлы
history		список введенных ранее команд
