# Базовые команды Linux

## Что вокруг

Терминал всегда находится в какой-то директории. Первые команды отвечают на три вопроса: где я, что здесь лежит и как попасть в другое место.

```bash
pwd                 # показать текущую директорию
ls                  # показать содержимое текущей директории
ls -l               # подробный список: права, владелец, размер, дата
ls -la              # включая скрытые файлы (их имена начинаются с точки)
cd /var/log         # перейти в /var/log
cd ..               # подняться на уровень выше
cd                  # вернуться в домашнюю директорию (как cd ~)
```

Пути бывают **абсолютные** и **относительные**. Абсолютный путь начинается с корня `/` и работает независимо от текущей директории:

```text
/var/log/nginx
```

Относительный путь отсчитывается от текущего места: если вы находитесь в `/var/log`, то `cd nginx` приведёт в `/var/log/nginx` (если такая директория существует).

Две точки `..` означают родительскую директорию, а тильда `~` — домашнюю.

В выводе `ls -l` сначала достаточно смотреть на имя и первый символ строки. Если строка начинается с `d`, перед вами директория, если с `-` — обычный файл.

## Чтение файлов командой cat

`cat` печатает содержимое файла прямо в терминал:

```bash
cat /etc/os-release
```

Пример вывода (он зависит от версии системы):

```text
NAME="Ubuntu"
VERSION_ID="24.04"
PRETTY_NAME="Ubuntu 24.04 LTS"
...
```

Для конфигураций и коротких файлов это быстрый способ заглянуть внутрь. Файл на десять тысяч строк `cat` тоже напечатает, но читать его так неудобно. Для длинных файлов лучше использовать `less`.

## Поиск по содержимому через grep

`grep` ищет строки, соответствующие шаблону. Команда особенно полезна для поиска ошибок в логах.

```bash
grep error /var/log/app.log       # строки со словом error
grep -i error /var/log/app.log    # без учёта регистра
grep -n error /var/log/app.log    # номера найденных строк
grep -r "listen" /etc/nginx/     # рекурсивный поиск по файлам каталога
```

Пути к логам здесь примерные: нужные файлы должны существовать.

### Пайп (`|`): вывод одной команды на вход другой

```bash
cat access.log | grep "500"
```

- `cat` выводит строки файла.
- `grep` оставляет строки, содержащие `500`.

Такая связка называется **пайпом**. На ней строится повседневная работа в терминале: одна команда получает данные, другая фильтрует, третья считает.

В этом конкретном случае можно проще: `grep "500" access.log`.

## Создание файлов и папок

`mkdir` создаёт директорию, а `touch` — пустой файл (или обновляет время изменения существующего).

```bash
mkdir reports                  # создать директорию reports
mkdir -p apps/web/logs         # создать всю вложенность
touch notes.txt                # создать пустой файл
echo "hello" > notes.txt       # записать строку в файл
cat notes.txt                  # проверить: hello
```

Флаг `-p` избавляет от создания вложенных директорий по одной. Символ `>` перенаправляет вывод команды в файл; **если файл существует, его содержимое будет перезаписано**.

## Копирование и перемещение

```bash
cp config.yaml config.yaml.bak    # копия файла рядом
cp -r site/ site_backup/          # копирование директории с содержимым
mv config.yaml /etc/myapp/        # переместить (если есть права доступа)
mv old_name.txt new_name.txt      # переименовать
```

Отдельная команда для переименования не нужна: `mv` умеет как перемещать, так и переименовывать. Флаг `-r` у `cp` означает «рекурсивно», то есть с содержимым вложенных директорий.

## Удаление файлов командой rm

```bash
rm notes.txt           # удалить файл
rm -r old_project/     # удалить директорию с содержимым
```

**Осторожно:** обычно `rm` не перемещает удалённое в корзину. Перед `rm -r` полезно проверить текущую директорию (`pwd`) и цель удаления (`ls`). Особенно внимательно проверяйте команды с `sudo`.

## Права на файлы

У каждого файла в Linux есть права: кто может его читать, изменять и выполнять. `chmod` меняет эти права:

```bash
chmod +x deploy.sh       # добавить право на выполнение
chmod 644 config.yaml    # права: владельцу чтение/запись, остальным чтение
```

Типичный сценарий: вы написали скрипт, а система отказывается его запускать, потому что у файла нет права на выполнение. Числа вроде `644` и `755` задают права для владельца, группы и остальных пользователей.

## Права администратора и sudo

`sudo` позволяет запустить команду с правами другого пользователя (по умолчанию — `root`), если у вас есть соответствующее разрешение:

```bash
sudo apt install htop              # установить пакет
sudo systemctl restart nginx       # перезапустить службу
sudo cat /etc/shadow               # прочитать защищённый системный файл
```

Не все системные команды обязательно требуют `sudo` — это зависит от операции и настроенных прав. Не добавляйте `sudo` «на всякий случай»: чем меньше команд выполняется с правами администратора, тем меньше риск случайно повредить систему.

## Шпаргалка

| Команда | Что делает | Пример |
|---|---|---|
| `pwd` | Показывает текущую директорию | `pwd` |
| `cd` | Переходит в другую директорию | `cd /var/log` |
| `ls` | Показывает содержимое директории | `ls -la` |
| `cat` | Выводит содержимое файла | `cat /etc/os-release` |
| `grep` | Ищет текст | `grep -i error app.log` |
| `mkdir` | Создаёт директорию | `mkdir -p apps/web` |
| `touch` | Создаёт пустой файл или обновляет временные метки | `touch notes.txt` |
| `cp` | Копирует файлы и директории | `cp -r site/ backup/` |
| `mv` | Перемещает и переименовывает | `mv old.txt new.txt` |
| `rm` | Удаляет файлы и директории | `rm -r old_project/` |
| `chmod` | Изменяет права на файл | `chmod +x deploy.sh` |
| `sudo` | Запускает команду с повышенными правами | `sudo apt update` |

## Что учить после этой десятки

Эти команды покрывают базовую навигацию и работу с файлами. Следующий слой — утилиты, которые превращают терминал в полноценный рабочий инструмент. Учить их все сразу необязательно.

| Утилита | Зачем нужна |
|---|---|
| `nano` | Простой текстовый редактор в терминале |
| `vim` | Ещё один распространённый терминальный редактор |
| `less` | Постраничный просмотр длинных файлов и логов |
| `tail -f` | Просмотр новых строк лога в реальном времени |
| `head` | Показать первые строки файла |
| `find` | Поиск файлов по различным условиям |
| `ps`, `top` | Просмотр процессов и нагрузки |
| `kill` | Отправка сигнала процессу |
| `systemctl` | Управление службами |
| `df -h`, `free -h` | Информация о диске и оперативной памяти |
| `curl` | Запросы к сайтам и API |
| `ssh`, `scp` | Подключение к серверу и передача файлов |
| `history` | История введённых команд |
